title: Requirements
description: Functional, non-functional requirements and scale assumptions for sorting large data sets.
---

## Functional Requirements

| Capability | Description |
|-----------|-------------|
| **Input ingestion** | Files (CSV, JSON, Parquet), DB tables, Kafka streams, user uploads |
| **Schema detection** | Auto-detect column types; manual override allowed |
| **Multi-key sort** | Single/multi-key with ascending/descending per key |
| **Partial sorting** | Top-K, bottom-K, K-th element without full sort |
| **Stable sort** | Preserve relative order of equal elements |
| **Deduplication** | Remove duplicates on configurable key(s) |
| **Pre-sort filter** | WHERE predicates (e.g., `date > '2026-01-01'`) applied before sort |
| **Output formats** | Sorted file, DB table, streaming output, API response |
| **Parallel execution** | Automatic parallelization; merge-sort across cluster |
| **Progress tracking** | ETA, progress %, bytes processed, current phase |
| **Result verification** | Checksum integrity of sorted output |

## Non-Functional Requirements

| Metric | Target |
|--------|--------|
| Sort throughput | 100 GB/hour/node (HDD); 500 GB/hour/node (SSD) |
| Max dataset size | 10 TB per sort job |
| Memory footprint | O(N^(1/3)) — never exceed 1 GB heap per node |
| Sort latency (1 TB, 10 nodes) | < 30 minutes |
| Fault tolerance | Recover from node failure without re-scanning input |
| Concurrency | 10 concurrent jobs on 10-node cluster |
| Data locality | Minimize network shuffling; compute-to-data |

## Scale Assumptions

| Parameter | Value |
|-----------|-------|
| Dataset size | 100 GB – 10 TB |
| Record size | Avg 1 KB (range: 100 B – 10 KB) |
| Records | 100M – 10B rows |
| Cluster | 5–100 nodes, 64 GB RAM, 1 Gbps, 1–4 TB local disk |
| Workload mix | 70% full sort, 20% top-K, 10% range filter + sort |

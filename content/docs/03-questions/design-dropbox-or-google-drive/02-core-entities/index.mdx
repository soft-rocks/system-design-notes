## FileReference (Folder membership)

| Field | Type | Notes |
|---|---|---|
| fileReferenceId | string (UUID) | Primary key |
| fileId | string (UUID) | FK → File |
| parentFolderId | string (UUID) | FK → File (where isDirectory=true) |
| name | string | Display name in parent |
| sortOrder | int | For ordering siblings |
| createdAt | timestamp | |

**Invariants:**
- A FileReference links a File to exactly one parent folder (tree structure).
- Circular references prevented by application-level constraint.

**Root namespace:** Each user has a virtual root folder (parentFolderId = null). All top-level items in the user's namespace reference this virtual root via null parentFolderId, avoiding the need for a separate root File record.

## Permission

| Field | Type | Notes |
|---|---|---|
| permissionId | string (UUID) | Primary key |
| fileId | string (UUID) | FK → File (or Folder) |
| userId | string (UUID) | FK → User |
| role | enum | owner / editor / viewer |
| inherited | boolean | true if derived from a parent share |
| createdAt | timestamp | |

**Inheritance:** Permissions cascade down the folder tree. Direct permissions override inherited ones.

**Tradeoff:** Storing explicit `inherited=true` rows simplifies permission lookups (no tree traversal needed) but multiplies storage for deep hierarchies. When parent permissions change, all descendant `inherited=true` rows must be invalidated — typically via a recursive batch job or event-driven update. At scale, consider computing inherited permissions on-read instead (traverse up the folder tree at query time).

## SyncOperation (journal)

| Field | Type | Notes |
|---|---|---|
| operationId | string (UUID) | Primary key |
| userId | string (UUID) | FK → User |
| fileId | string (UUID) | FK → File |
| operationType | enum | create / update / delete / move / share |
| sourceState | string (JSON) | Metadata snapshot (path, name, size) before change |
| targetState | string (JSON) | Metadata snapshot (path, name, size) after change |
| createdAt | timestamp | Monotonically increasing |
| status | enum | pending / synced / conflict |

**Invariants:**
- This journal is the append-only source of truth for sync state machines.
- Consumed by the sync engine to propagate changes to connected devices.
